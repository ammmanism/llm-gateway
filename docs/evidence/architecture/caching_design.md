# Two-tier cache and cost attribution

## What is implemented

`TwoTierCache` (`src/llm_gateway/cache/two_tier.py`) checks two tiers in order:

1. **Exact tier** — SHA-256 of the normalized prompt plus a namespace hash over
   `tenant_id`, `model`, and request parameters (`temperature`, `max_tokens`).
   Values are stored through `CacheManager`, which uses Redis when `REDIS_URL`
   is set and a TTL-aware in-process dictionary otherwise.
2. **Semantic tier** — a per-namespace FAISS HNSW index (`METRIC_INNER_PRODUCT`
   over normalized embeddings). A hit must meet the configured cosine
   similarity threshold and be unexpired.

Namespaces are keyed by tenant, model, and generation parameters, so a cached
answer cannot cross tenants, models, or sampling settings.

## Configuration

`configs/caching.yaml` is the source of truth:

```yaml
strategies:
  exact:
    ttl: 3600
  semantic:
    similarity_threshold: 0.85
```

`TwoTierCache.from_config()` reads these values at startup. A threshold outside
`[0, 1]` raises `ValueError` instead of silently accepting a broken config.

The `0.85` default is data-driven: `benchmarks/semantic_threshold_sweep.py`
replays 24 paraphrase queries and 24 negatives through the real FAISS index at
thresholds 0.80/0.85/0.90/0.95. On this set `0.95` matched nothing, `0.90`
matched 12.5% of paraphrases, `0.85` matched 29.2% with zero hard-negative false
positives, and `0.80` matched 37.5% but let one adjacent-intent query through
(`data/evidence/semantic_threshold_sweep.csv`).

## `live_data` bypass

`POST /generate` accepts `live_data: bool = false`. When it is true the cache is
neither read nor written for that request:

```python
cache_enabled = request.use_cache and not request.live_data
```

This is for prices, inventory, and other answers where a stale cache hit is
worse than paying for a fresh completion. The integration test
`tests/routing/integration/test_gateway_phase2.py::test_live_data_bypasses_cache`
asserts that the second identical `live_data` request is still a miss.

## Embedding backend

`EmbeddingEngine` prefers `sentence-transformers/all-MiniLM-L6-v2`. If the
optional `ml` extra or the model weights are unavailable, it logs a warning and
falls back to `HashingEmbedder`, a deterministic signed feature-hash embedder.
The fallback keeps the cache functional offline and makes tests deterministic;
it is **not** claimed to match neural embedding quality.

## Cost ledger

`src/llm_gateway/billing/cost_ledger.py` writes one SQLite row per
`(request_id, attempt)`:

| column | meaning |
| --- | --- |
| `request_id`, `attempt` | idempotency key; retries/fallbacks get distinct attempts |
| `tenant_id` | attribution boundary |
| `provider`, `model` | actual provider/model that served the attempt |
| `prompt_tokens`, `completion_tokens` | provider usage when available, else whitespace estimate |
| `cost_usd` | cost computed by `NexusCostTracker` |
| `cache_hit` | true for a served cache hit (cost 0) |
| `usage_source` | `provider`, `estimated`, or `cache` |
| `occurred_at`, `day` | UTC timestamp and UTC day bucket |

`GET /v1/costs?date=YYYY-MM-DD[&model=...]` returns the authenticated tenant's
day summary: request count, cache hits, token totals, total cost, per-model
costs, and the raw entries.

## Evidence

`data/evidence/cost_ledger_sample.csv` is generated by
`benchmarks/cost_attribution_demo.py`. The script drives the real FastAPI app
through `TestClient` with a deterministic fake provider, then exports rows from
the gateway's own SQLite ledger. It contains five requests: four provider
completions and one exact cache hit recorded at zero cost.

Run it with:

```bash
python benchmarks/cost_attribution_demo.py
```
