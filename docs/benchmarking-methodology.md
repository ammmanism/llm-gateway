# Benchmarking methodology

The committed evidence is generated by scripts in `benchmarks/` and written to
`data/evidence/`. Charts are rendered from those files by
`benchmarks/plot_evidence.py`; they do not contain hard-coded data.

## Controls

- Provider calls use deterministic fakes so gateway cost is isolated from
  upstream network variance.
- Gateway overhead uses 500 interleaved direct/gateway sample pairs.
- Semantic caching uses 24 paraphrases, 12 unrelated negatives, and 12 hard
  negatives at thresholds 0.80/0.85/0.90/0.95.
- Failover uses a deterministic failing provider and a fake breaker clock where
  applicable; real sleeps measure the configured recovery timeout.
- Redis consistency uses two independent worker processes against Redis 7.
- OTLP evidence comes from a real OpenTelemetry Collector file exporter.
- Coverage uses statement and branch measurement from the full test suite.

## Environment

The committed run used Windows 11, Python 3.12, CPU FAISS, and local Redis 7.
Exact hardware and timing vary; the CSV records the sample counts and
concurrency used.

## Reproduce

```bash
REDIS_URL=redis://localhost:6379/0 OTEL_SDK_DISABLED=true \
  python benchmarks/run_all.py
```

See `benchmarks/results/README.md` for the evidence index. Execution-status JSON
under `benchmarks/results/` is ignored; the authoritative outputs are committed
under `data/evidence/`.
